## 🔁 שיטת העבודה — לולאת בדיקה לכל סטטוס
**דרישות מקדימות:** `.env.local` בשורש הריפו עם `SUPABASE_PROJECT_REF`, `SUPABASE_ACCESS_TOKEN`, ו-`WARMING_TEST_PHONES=0512310702`. (מספר בדיקה חדש? לשלוח ממנו פעם אחת הודעה לבוט של שיווק שותפים, +972 55-991-7038, כדי שתיווצר שיחה, ולהוסיף אותו לרשימה.)

1. **הזרקת הסטטוס:**
   ```bash
   bun run scripts/admin/warming-test-trigger.ts 0512310702 <status_sub>
   ```
   הסקריפט משחזר בדיוק את מה ש-`crm-status-webhook` עושה, מאפס את שיחת הבדיקה, ומכריח את הפתיח לצאת **עכשיו** (מדלג על ה-delay). אין צורך ב-n8n.
2. **תוך ~דקה** מגיע לטלפון הבדיקה "מה קורה?".
   ⚠️ *(כרגע לא חל — ה-dispatcher בפרוד ישן ואין בו את ההשהיה, אז הפתיח יוצא מיד. יחזור לחול אחרי שה-dispatcher ייפרס.)* **ה-dispatcher מעכב את הפתיח אם הבודק כתב לבוט ב-60 הדקות האחרונות** (`WARMING_QUIET_MINUTES`, "לא דופקים על שיחה חיה"), ויש גם מרווח של 90 שניות בין פתיחים. בסבב בדיקות רצוף זה יקרה כל הזמן. **זה לא חוסם:** ההקשר של הסטטוס כבר על השיחה מהרגע שהסקריפט רץ, אז הבודק פשוט שולח הודעה ראשון ("היי") והבוט עונה כבר עם הסטטוס החדש. פתיח שעוכב ייצא מאוחר יותר — הרצה חוזרת של הסקריפט מבטלת אותו.
3. **תדריך לבודק** (בעברית): מה לענות כדי לשחק את ההתנגדות של הסטטוס, ומה הבוט אמור לעשות — לפי סעיף הסטטוס במסמך האפיון. תמיד לבקש גם לבדוק תשובה פושרת ("סבבה", "הכל טוב") — שם נפלו רוב הבאגים.
4. **שיפוט:** הבודק שולח צילום מסך / תיאור. השווה מול האפיון: עונה למה שהליד אמר? לא חוזר להכשרת ליד טרי? לא מקפל? לא חושף שהוא "יודע"? מנטרל לפני זום? טון חד-אבל-עדין, ברור, לא רובוטי?
5. **תיקון** (ראה הסעיף הבא) → פריסה אם צריך → **בדיקה חוזרת של אותו סטטוס** עד ש-Izak/הבודק מאשר → הסטטוס הבא.

### איך מתקנים — שתי ידיות
- **בעיה שתחזור בסטטוסים אחרים** (טון, קיפול, חשיפה, דחיפה לזום...) → כלל בבלוק המשותף `warmingContextBlock.ts`, בתוך "core behaviour rules", **לפני** `## How to handle this lead`. להוסיף טסט ב-`warmingContextBlock.test.ts` (אם הבלוק גדל — להגדיל את ה-buffer בטסט ה-clamp). `bun run test` → commit → **פריסה** (פקודה למטה; ה-classifier של Claude Code חוסם לקלוד לפרוס בעצמו — הבודק מריץ). זה המנוף הכי חזק — רוב התיקונים עד עכשיו היו כאלה.
- **בעיה ספציפית לסטטוס** → לעדכן את `warming_instructions` של אותה שורה ב-DB (חי מהתור הבא, בלי פריסה) **וגם** את אותה שורה ב-`0049_warming_instructions_affiliate.sql` כדי ש-git יישאר מקור אמת.

כללים לטקסטים: עברית, קול Izak, **מיינדסט ולא תסריט** (הבוט לא מצטט אותם), guard-safe — בלי ₪/$/שקלים/דולר/סכומים/"תשלומים"/הנחה/הבטחת הכנסה (ה-regex וה-judge חוסמים אוטומטית → הליד מקבל **שתיקה**).

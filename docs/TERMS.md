# מילון מושגים ללמידה

רשימת מושגים טכניים שעולים בפרויקט הזה, עם הסבר בשפה פשוטה ואיפה זה מופיע אצלנו. **זה קובץ ללמידה** — לא מסמך אמת. מונחי הדומיין (Lead, Progression, Bot-Booked Zoom וכו') נמצאים ב-[CONTEXT.md](../CONTEXT.md); ההחלטות הארכיטקטוניות ב-[CLAUDE.md](../CLAUDE.md).

פורמט: **מושג** — מה זה בפשטות — *איפה אצלנו*.

---

## 1. קוד, תיקיות וזרימת עבודה

- **`src`** — קיצור של *source*. תיקיית קוד המקור של האפליקציה. *אצלנו: `src/` = הדשבורד (React); הקוד של הבוט עצמו יושב דווקא ב-`supabase/functions/`.*
- **repo (repository)** — התיקייה שגיט עוקב אחריה, כולל כל ההיסטוריה. *אצלנו: `RicherLTD/richer-ai-agents-hub`.*
- **branch (ענף)** — עותק עבודה מקבילי של הקוד, כדי לא לגעת ב-`main` עד שזה מוכן. *אצלנו: `feat/...`, `fix/...`, `docs/...`.*
- **commit** — "נקודת שמירה" עם הסבר מה שונה ולמה. *אצלנו: כל commit חייב הסבר באנגלית.*
- **PR (Pull Request)** — בקשה למזג ענף ל-`main`, עם מקום לביקורת לפני שזה נכנס. *אצלנו: השער היחיד ל-production.*
- **diff** — ההפרש בין שתי גרסאות: מה נוסף ומה נמחק. *אצלנו: מה שקוראים ב-PR.*
- **branch protection** — כלל בגיטהאב שאוסר לדחוף ישר ל-`main`. *אצלנו: מופעל.*
- **merge / revert** — מיזוג שינוי פנימה / ביטול שינוי שכבר נכנס. *`git revert` = החזרה בפקודה אחת.*
- **`git blame`** — מציג מי שינה כל שורה ומתי. *אצלנו: הסיבה שה-prompts נשארים כקבצים ב-git ולא ב-UI.*
- **lint** — בדיקה אוטומטית של סגנון ושגיאות נפוצות בקוד. *אצלנו: `bun run lint` (ESLint) — **מדלג על `supabase/functions/`**.*
- **typecheck** — בדיקה שהטיפוסים מסתדרים, בלי להריץ את הקוד. *אצלנו: `tsc --noEmit` — מכסה רק `src/`.*
- **build** — הידור/אריזה של הקוד לגרסה שמוגשת למשתמש. *אצלנו: `bun run build` (Vite).*
- **CI (Continuous Integration)** — רובוט שמריץ בדיקות על כל PR. *אצלנו: `.github/workflows/ci.yml` — typecheck + lint + build, **בלי טסטים**.*
- **dependency** — ספרייה חיצונית שהקוד שלנו משתמש בה. *אצלנו: מעט מאוד — Anthropic SDK, Supabase, React.*
- **package manager** — הכלי שמתקין dependencies. *אצלנו: `bun`.*
- **monorepo** — ריפו אחד שמכיל כמה פרויקטים. *אצלנו: לא בדיוק monorepo, אבל דשבורד + בוט באותו ריפו.*

## 2. TypeScript / JavaScript

- **type / interface** — הצהרה על צורת הנתונים (למשל "לאובייקט הזה יש `q1_age` שהוא מספר או null"). *אצלנו: `ExtractedMemory`.*
- **strict mode** — TypeScript קפדני: מכריח לטפל ב-null ואוסר קיצורים. *אצלנו: מופעל, ואסור לכבות.*
- **`any`** — "טיפוס כלשהו" — מבטל את כל ההגנה של TypeScript. *אצלנו: אסור, חוץ מפרמטרים של ה-SDK שהטיפוס שלו לא מכסה tools.*
- **`unknown`** — כמו `any` אבל בטוח: חייבים לבדוק מה זה לפני שמשתמשים. *אצלנו: התחליף המותר ל-`any`.*
- **async / await / Promise** — קוד שממתין לדבר איטי (רשת, DB) בלי להקפיא את כל התוכנית. *אצלנו: כמעט כל שורה בבוט.*
- **closure** — פונקציה שזוכרת משתנים מהמקום שבו נוצרה. *אצלנו: `flushTurnObservability` זוכרת את `langfuseTraceId`.*
- **fire-and-forget** — שולחים בקשה ולא מחכים/לא נכשלים אם היא נכשלת. *אצלנו: כל השליחות ל-Langfuse — תיעוד לא יעכב תשובה לליד.*
- **buffer** — לאסוף נתונים בצד ולשלוח אחר כך במקבץ. *אצלנו: ציוני ה-guard/judge נאספים ונשלחים אחרי שההודעה יצאה לליד.*

## 3. בסיס נתונים (Postgres / Supabase)

- **schema** — המבנה: אילו טבלאות ועמודות קיימות. *אצלנו: מנוהל דרך migrations.*
- **migration** — קובץ SQL ממוספר שמשנה את ה-schema, כדי שהשינוי יהיה מתועד וניתן לשחזור. *אצלנו: `supabase/migrations/0001..0045`.*
- **drift** — כשה-DB בפועל שונה ממה שהקבצים אומרים. *אצלנו: קיים — `0040` מוחק constraint שאף migration לא יצר, ו-prompt v19 קיים רק ב-DB.*
- **column / row** — עמודה (שדה) / שורה (רשומה). *אצלנו: `conversations.lead_phone` = עמודה.*
- **index** — "אינדקס" שמאיץ חיפוש בעמודה, כמו מפתח בסוף ספר. *אצלנו: על `last_inbound_at`, על טלפון.*
- **unique constraint** — כלל שאוסר שתי שורות עם אותו ערך. *אצלנו: `(agent_id, lead_phone)` — מונע שיחה כפולה.*
- **RLS (Row Level Security)** — הרשאות ברמת השורה: מי מורשה לראות אילו שורות. *אצלנו: מ-0018 נתוני לידים = admin בלבד.*
- **policy** — כלל RLS ספציפי. *אצלנו: `mooz_webhook_events` עם `USING (true)` = פרצה.*
- **upsert** — "עדכן אם קיים, אחרת צור". *אצלנו: כתיבת `lead_memory`.*
- **jsonb** — עמודה שמחזיקה JSON שאפשר לתחקר. *אצלנו: `error_logs.context`.*
- **enum** — רשימה סגורה של ערכים מותרים. *אצלנו: `tag_enum` — שמכיל 4 ערכים מתים.*
- **RPC / SQL function** — פונקציה ששמורה בתוך ה-DB ומריצים אותה בשאילתה. *אצלנו: `claim_scheduled_messages`, `template_funnel`.*
- **`SECURITY DEFINER` / `SECURITY INVOKER`** — האם הפונקציה רצה בהרשאות הכותב או בהרשאות הקורא. *אצלנו: `template_funnel` הוא INVOKER — ולכן מחזיר אפסים למי שאינו admin.*
- **`SKIP LOCKED`** — "דלג על שורות שמישהו אחר כרגע עובד עליהן". *אצלנו: מונע שליחת אותו טמפלייט פעמיים.*
- **race condition** — שני תהליכים עושים את אותו דבר בו-זמנית ודורסים אחד את השני. *אצלנו: `agent_lock_taken_at`, `claimed_at`.*
- **idempotent** — אפשר להריץ פעמיים והתוצאה זהה (בלי כפילויות). *אצלנו: `meta_message_id` unique; `mooz_webhook_events`.*
- **backfill** — למלא נתונים היסטוריים בדיעבד. *אצלנו: התוכנית למלא `lead_memory` ל-1,349 שיחות.*
- **shadow table** — טבלה זמנית לכתוב אליה כדי להשוות לפני שנוגעים בנתונים האמיתיים. *אצלנו: שלב הביניים המוצע ב-backfill.*
- **pgvector** — הרחבה של Postgres לאחסון וחיפוש embeddings. *אצלנו: הדרך לשדרג את ה-brain.*

## 4. AI / מודלים

- **prompt** — הטקסט שמגדיר לבוט מי הוא ואיך להתנהג. *אצלנו: `prompts/<agent>/main/vN.md`.*
- **system prompt** — ההוראות הקבועות שנשלחות בכל תור, לפני השיחה עצמה. *אצלנו: ~16KB בכל הודעה.*
- **token** — פיסת טקסט (בערך 3–4 תווים). התמחור והמגבלות נמדדים בטוקנים. *אצלנו: `tokens_input`/`tokens_output` בכל הודעה.*
- **context window** — כמה טקסט המודל יכול "להחזיק" בתור אחד. *אצלנו: הסיבה שמסמך brain גדול דוחק את היסטוריית השיחה.*
- **prompt caching** — הנחה על טקסט שחוזר בכל קריאה, אם הוא נשלח זהה. *אצלנו: `cacheReadTokens` — רוב העלות של ה-system prompt.*
- **embedding** — הפיכת טקסט לרשימת מספרים שמייצגת את המשמעות שלו; לטקסטים דומים יוצאים מספרים דומים, וכך אפשר למצוא "מה הכי דומה לשאלה הזאת". *אצלנו: עדיין לא בשימוש — הבסיס לשדרוג ה-brain.*
- **chunking** — חיתוך מסמך לפיסות קטנות לפני יצירת embeddings. *אצלנו: מה שחסר כדי להפסיק לשלוח 200K תווים.*
- **retrieval / RAG** — לשלוף רק את הקטעים הרלוונטיים מתוך ידע גדול ולצרף אותם לשאלה. *אצלנו: החלופה ל"דחיפת כל המסמכים".*
- **tool use (function calling)** — המודל מבקש להריץ פונקציה שהגדרנו (למשל "תביא לי זמנים פנויים"), מקבל תשובה, וממשיך. *אצלנו: `list_available_slots`, `book_meeting` של Mooz.*
- **`tool_choice` (forced tool)** — לכפות על המודל לקרוא לכלי מסוים, כך שהתשובה תמיד בפורמט שביקשנו. *אצלנו: התיקון של ה-extractor — במקום לבקש JSON כטקסט.*
- **structured output** — לקבל נתונים בפורמט מובנה במקום טקסט חופשי. *אצלנו: מה ש-forced tool call נותן.*
- **prefill (assistant prefill)** — "לשים מילה ראשונה בפה של המודל" כדי לכוון את הפורמט. *אצלנו: הטריק שנשבר — `{` פורש כטוקן פקודה ולא כתחילת JSON.*
- **thinking / reasoning** — מצב שבו המודל "חושב" לפני שהוא עונה. *אצלנו: `thinking: adaptive` בתשובת הסוכן.*
- **hallucination** — המודל אומר משהו שנשמע נכון אבל לא נכון. *אצלנו: `invented_meeting_time` — הבוט המציא שעה שלא הוצעה.*
- **guardrail / guard** — בדיקה אוטומטית שחוסמת תשובה בעייתית לפני שליחה. *אצלנו: `validateAgentReply` (regex) ואחריו ה-judge.*
- **LLM-as-judge** — מודל זול שמדרג את תשובת המודל היקר. *אצלנו: `judgeReply` עם Haiku.*
- **degrade-open / fail-closed** — כשמערכת עזר נופלת: להמשיך בכל זאת / לעצור. *אצלנו: ה-judge נופל → ממשיכים (open); Mooz לא עונה → לא שולחים (closed).*
- **dataset / example / experiment** — אוסף קפוא של מצבים אמיתיים + מה נכון לענות, כדי לבדוק prompt חדש בלי לגעת בלידים. *אצלנו: התוכנית מ-Langfuse.*
- **eval (evaluation)** — מדידה מסודרת של איכות פלט המודל. *אצלנו: מה שנבנה סביב ה-scores.*

## 5. תשתית ואבטחה

- **edge function** — פונקציה קטנה שרצה בענן לפי דרישה, בלי שרת שאנחנו מתחזקים. *אצלנו: 18 פונקציות Deno ב-Supabase.*
- **Deno / Node / bun** — סביבות הרצה של JavaScript/TypeScript. *אצלנו: Deno בפונקציות, bun לפיתוח מקומי.*
- **webhook** — כתובת URL שמערכת חיצונית קוראת לה כשקורה משהו. *אצלנו: HookMyApp → `whatsapp-webhook`; Mooz → `mooz-webhook`.*
- **HMAC (חתימה)** — חתימה קריפטוגרפית שמוכיחה שההודעה באמת מהשולח שטוען. *אצלנו: `X-Hub-Signature-256`, וגם קישורי ה-embed.*
- **JWT** — "כרטיס כניסה" חתום שמוכיח מי המשתמש. *אצלנו: מה ש-`requireAdmin` בודק.*
- **`anon key` מול `service_role`** — מפתח ציבורי שמוגן ב-RLS מול מפתח־על שעוקף RLS. *אצלנו: `service_role` נשאר בשרת בלבד, אף פעם לא ב-client.*
- **environment variable (env var) / secret** — הגדרה או סוד שמוזרקים לקוד מבחוץ. *אצלנו: `.env.local` (מקומי), Supabase secrets (production).*
- **cron / pg_cron** — מתזמן שמריץ משהו כל X זמן. *אצלנו: הדיספאצ'ר כל דקה.*
- **queue / DLQ (Dead Letter Queue)** — תור; ו"תור המקרים שנכשלו" שאפשר לנסות שוב. *אצלנו: `failed_messages` + `dlq-replay`.*
- **retry / exponential backoff** — לנסות שוב, עם המתנה שמתארכת בכל ניסיון. *אצלנו: `anthropicRetry`.*
- **timeout** — כמה זמן מחכים לפני שמכריזים על כשל. *אצלנו: 110s על קריאות Anthropic, מתחת ל-150s של הפונקציה.*
- **iframe / CSP `frame-ancestors`** — הטמעת דף בתוך דף אחר, וכלל שמגביל מי מורשה להטמיע. *אצלנו: `/embed/c` בתוך כרטיס Fireberry.*
- **PII** — מידע אישי מזהה (טלפון, אימייל, תוכן שיחה). *אצלנו: נשלח ל-Langfuse Cloud — החלטה שעדיין פתוחה.*
- **SAST / Snyk** — סריקת קוד אוטומטית לאיתור בעיות אבטחה. *אצלנו: חובה לפני push.*

## 7. מדידה ותצפית (Observability)

- **telemetry** — נתוני מעקב שהמערכת מייצרת על עצמה. *אצלנו: 77% מ-`error_logs` הן טלמטריית מסירה, לא שגיאות.*

- **latency** — כמה זמן לקח. *אצלנו: `latency_ms` בכל הודעה.*

## 8. סטטיסטיקה ומסקנות

- **baseline** — הביצועים הקיימים, שמולם מודדים שיפור. *אצלנו: ~20 Bot-Booked Zoom בשבוע.*
- **conversion rate** — אחוז שעבר משלב לשלב. *אצלנו: 57% מהקוראים עונים; ~5% מהלידים קובעים.*
- **cohort** — קבוצה שמשתפת מאפיין, שמודדים אותה בנפרד. *אצלנו: כל הודעות prompt v19.*
- **attribution (ייחוס)** — למי מגיע הקרדיט להצלחה. *אצלנו: `zoom_booked_by` — הבוט או הליד עצמו.*
- **leading indicator** — סימן מקדים ומהיר שמנבא את התוצאה האיטית. *אצלנו: Progression מנבא Booked Zoom.*
- **A/B test** — להריץ שתי גרסאות במקביל ולהשוות. *אצלנו: בעייתי — הנפח קטן מדי.*
- **sample size / statistical power** — כמה נתונים צריך כדי שהבדל יהיה אמיתי ולא מקרי. *אצלנו: ~3,400 לידים לכל גרסה = 7 שבועות.*
- **noise (רעש)** — תנודות מקריות שנראות כמו ממצא. *אצלנו: הסיבה שמסקנה שבועית על זומים תטעה.*
- **selection bias** — להסתכל רק על תת-קבוצה ולהכליל ממנה בטעות. *אצלנו: ללמוד מ"לא ענו" בלי להפריד את מי שההודעה לא הגיעה אליו בכלל.*
